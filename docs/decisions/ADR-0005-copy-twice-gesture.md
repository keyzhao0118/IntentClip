# ADR-0005：Ctrl+C+C 双复制触发手势

- 状态：已接受，需通过原型验证误触率
- 日期：2026-08-03

## 背景

用户希望在复制文本的自然动作中直接唤起面板，而不是先复制、再记忆另一组快捷键。Windows 的标准全局热键接口只能表达一次组合键，不能直接表达连续两次 `Ctrl+C`；同时 `Ctrl+C` 已属于前台应用，不能被 IntentClip 抢占。

## 决策

默认手势定义为：两次有效的 `C` key-down 均发生在 Ctrl 按下期间，两次之间各有 key-up，间隔不超过默认 500 ms。应用只观察这一有限状态，不吞键、不注入键、不阻止前台应用完成两次复制。第二次按键后等待剪贴板序列更新，再读取纯文本并显示面板。

用户可以暂停该手势、调整 300–800 ms 的窗口，或切换到普通全局组合键。低级钩子不可用时必须自动降级，不得让托盘进程反复重试或静默失效。

实现使用 Windows 文档化接口；钩子回调只维护时序并投递事件，剪贴板读取和面板唤起在正常事件循环中完成。`GetClipboardSequenceNumber` 用于判断第二次复制的内容是否完成更新，不能假设按键事件到达时数据已经可读。

## 后果

手势高度贴合产品心智，但用户平时为确保复制而快速按两次 `Ctrl+C` 时可能误触。M1/M2 必须测量误触率、不同软件的剪贴板延迟和安全软件兼容性；若误触不可接受，可把默认改为普通快捷键，同时保留双复制作为可选能力。
