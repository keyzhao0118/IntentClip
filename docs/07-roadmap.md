# 路线图与质量门禁

## M0：立项基线（当前）

交付物：产品章程、PRD、体验规格、架构、隐私、商业化、商店发布手册和 ADR。

退出条件：核心产品边界无矛盾；所有高风险假设都有验证方法；不以“开发时再说”替代影响架构的决策。

## M1：可行性验证

目标：用最少 UI 证明本地模型的质量和性能。

- 建立至少 500 条去标识化、覆盖中英混合的意图基准集。
- 对 3–5 个候选模型、2–3 个量化档位做同一套测量。
- 验证受约束 JSON、取消、长文本、低内存和冷启动。
- 完成每个模型的许可与再分发审计。

退出条件：至少一个候选同时达到 PRD 的质量阈值和最低硬件性能预算；否则缩小能力或重新选型，不进入完整 UI 开发。

## M2：交互原型

目标：验证产品形态而非视觉装饰。

- 完成首次启动、拾意浮层、结果、模型、隐私五个可点击流程。
- 至少 5 名目标用户完成规定任务。
- 确认快捷键心智、低置信度表达、模型下载接受度和隐私理解。

退出条件：核心任务成功率至少 80%，重大信任误解关闭。

## M3：工程骨架与端到端切片

目标：一条真实链路可安装运行。

- CMake/vcpkg/CI、Qt 壳层、工作进程、IPC、一个模型、一个动作。
- Release 日志脱敏、崩溃隔离、单元与契约测试。
- 初版 MSIX 可安装、升级、卸载。

退出条件：干净机器从安装到复制结果可完成；工作进程崩溃不影响主进程。

## M4：MVP 完整功能

- 完成全部 P0 意图和异常状态。
- 完成模型管理、设置、许可、反馈和数据清除。
- 完成 DPI、键盘、高对比度和多显示器测试。

退出条件：PRD P0 全部验收，P1 不阻塞发布。

## M5：封闭测试与商店候选

- 完成 WACK、SBOM、隐私对照、第三方 notices 和商店素材。
- 测试最低/推荐硬件、断网、弱网、升级和卸载。
- 受控用户测试两周，关闭 P0/P1 缺陷。

退出条件：无已知数据泄漏、安装破坏或核心崩溃；审核备注能让陌生测试者独立完成验证。

## M6：公开发布与验证

- 分阶段发布，优先监控崩溃和模型准备失败。
- 发布后 2–4 周只修质量与理解问题，不急于扩功能。
- 达到留存与频次阈值后再进入 Pro 设计。

## Definition of Done

每个功能完成必须同时满足：需求与空/错/取消状态明确；代码评审和测试通过；无原文日志；键盘可用；中英文文案齐全；性能预算不退化；涉及数据/依赖/商店表述时文档已同步。

## 最高风险台账

| 风险 | 早期信号 | 缓解 |
|---|---|---|
| 小模型识别质量不足 | Top-1 低、低置信度频繁 | 缩窄意图、规则+模型混合、重新选型 |
| 首次模型下载流失 | 向导退出和下载失败高 | 更小模型、续传、提前说明、评估内置微型模型 |
| 低配设备体验差 | 加载慢、内存压力、系统卡顿 | 轻量档、资源预检、线程限制、最低要求 |
| Qt/模型许可履约遗漏 | notices 或来源不完整 | 自动生成 SBOM/notice、发布门禁、法律复核 |
| 商店因 AI/隐私被拒 | 元数据或反馈入口不足 | 提交前逐条映射政策、提供审核说明 |
| 免费但不可持续 | 留存低、支持/CDN 成本高 | 先验证频次，模型增量交付，推迟云成本 |
| 范围膨胀 | P1/P2 挤压稳定性 | 以 P0 和里程碑退出条件为唯一排期依据 |

## 当前开放问题

1. 最低硬件画像和性能预算基准机尚未锁定。
2. 默认模型与量化档位必须经 M1 决定。
3. 模型 CDN、商店可选包或内置微型模型的成本/审核对比待验证。
4. 发布主体采用个人还是公司开发者账户待确认。
5. 隐私政策与支持站点的域名、主体和联系渠道待建立。
