# 商业化策略

## 1. 原则

免费不是没有商业设计。MVP 的任务是建立使用频率、口碑和可信品牌，同时预留收费能力；但不得用上传用户文本、出售数据、强制登录或侵入式广告换收入。

## 2. 推荐模式：可信的本地 Freemium

### 永久免费的核心

- 本地意图识别与六类核心动作。
- 一个经过验证的默认模型。
- 基本快捷键、复制结果、隐私控制和模型删除。
- 安全修复、兼容性更新和数据导出。

### 候选 Pro 权益

- 自定义意图、提示模板和动作组合。
- 多配置档案、批量处理和高级结果对比。
- 更多本地模型档位与硬件加速配置助手。
- 更强的本地历史搜索、模板库和导出格式。
- 优先体验新能力，但不能将安全修复设为付费。

首个付费版本优先考虑一次性“Pro 永久版”，降低本地工具采用订阅带来的反感。只有在持续提供模型适配、模板内容或同步服务后，才评估订阅。免费版不放第三方广告。

## 3. 收入路径

1. **近期**：免费 MVP 获取真实留存与质量数据，不接支付。
2. **验证后**：Microsoft Store 内购解锁 Pro，应用启动时离线缓存已验证权益。
3. **后期**：面向团队提供可管理配置、离线部署、许可审计包和支持服务。
4. **可选**：独立的“支持者版”可提供非功能性权益，但不能使用误导性捐赠文案。

Microsoft Store 当前允许 PC 非游戏产品对应用内数字商品或服务使用 Microsoft Store 内购或安全第三方支付。首个消费者付费版本选择 Store 内购，理由是用户信任、退款和权益恢复路径更统一；通过 `IEntitlementProvider` 抽象，避免业务层被支付平台锁死。

## 4. 不采用的模式

- 出售、共享或利用剪贴板文本训练模型。
- 默认开启遥测后通过用户画像变现。
- 广告注入结果、浮层或剪贴板工作流。
- 免费版故意制造性能问题或隐藏数据清除能力。
- 通过下载未审核可执行模块动态扩展付费功能。

## 5. 商业指标

在发布前不以下载量代替价值。按漏斗观察：

- 商店页 → 安装转化率。
- 安装 → 首次成功率。
- 首次成功 → 次日/7 日留存。
- 每周活跃用户的人均成功动作数。
- 推荐动作采纳率、重试率和停止率。
- Pro 页面查看 → 试用/购买转化率。
- 退款率、崩溃率、模型下载失败率与支持工单率。

任何分析都优先由用户本地查看；若未来上传聚合事件，需单独设计数据字典、同意、最小化和保留期限。

## 6. 定价验证

不要在产品价值尚未验证时锁死价格。公测后通过用户访谈和商店市场测试评估三个一次性价格档位。决策输入包括 7 日留存、周使用频次、Pro 功能使用意愿、退款率、商店抽成、增值税/销售税处理、证书与 CDN 成本。

## 7. 成本模型

即使推理在本地，仍存在开发者账户、代码签名、模型 CDN 流量、网站与隐私政策托管、支持、崩溃收集、设计素材和合规审查成本。模型下载应支持缓存与续传，避免更新应用时重复下载同一权重；模型和应用分离也是控制带宽成本与发布节奏的关键。

## 8. 商业化门禁

只有满足以下条件才上线付费：免费核心稳定；权益可离线恢复；购买、退款、换机和卸载重装均已测试；商店元数据明确价格与范围；没有将既有付费价值从老用户移除；支持与隐私渠道可持续运行。
